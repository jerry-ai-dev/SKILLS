## 一、阶段三在整个学习路线中的位置

### 四阶段路线回顾

| 阶段 | 名称 | 解决的问题 | 输出物 |
|------|------|-----------|--------|
| 一 | PyTorch 入门 | **会用工具** | 能自己搭 mini-GPT、会用 HuggingFace 加载/微调 |
| 二 | 后训练理论深化 | **懂原理** | 能推导 SFT loss、PPO/GRPO 公式、KL 约束 |
| **三** | **开源项目研读（本阶段）** | **知道怎么做** | 能看懂 TRL/Open-R1，整理出可复用的代码模式 |
| 四 | 实战与论文撰写 | **自己能做** | 一个 SFT+GRPO 的项目 + 一篇论文 |

### 阶段三是一座桥

阶段二让你**懂公式**：`L_SFT = -∑ log π(y|x)`、PPO 的 clipped objective、GRPO 的 group-relative advantage、KL 罚项……  
阶段四要你**做项目**：自己搭 pipeline、自己跑训练、自己调参、自己写论文。

中间有一个巨大的鸿沟：**理论公式 → 工程代码**。
- 公式里写的是 `log π(y|x)`，工程代码里是 `model(input_ids, labels=labels).loss`——为什么这两个等价？labels 里的 -100 是干嘛的？
- 公式里写的是 advantage `Â = (r - mean)/std`，工程代码里是 `GRPOTrainer._compute_rewards()` 返回一个 tensor，再被 `_compute_loss()` 用——这两步之间发生了什么？数据怎么从 prompt 一路变成 advantage？

阶段三就是**填这条鸿沟**。它不教新理论，也不让你跑大规模训练，只做一件事：**把公式读成代码**。

### 为什么不能跳过这一段直接做项目？

如果阶段二之后直接进阶段四，你会遇到三类卡点：
1. **不会拼装**：知道 SFT 要做 prompt masking、知道 GRPO 要采样多条 response，但**不知道这些步骤在工业级代码里长什么样、谁负责哪一步**。
2. **不会调试**：训练跑起来 loss 是 0、是 NaN、根本不下降——但你不知道去 trainer 的哪一行打断点，因为你从来没见过 trainer 内部什么样。
3. **不会复用**：每写一行都从零造轮子，最后做出来的是个"玩具"，迁移不到真实任务。

阶段三的核心价值：**把一线项目的工程模板内化成你的肌肉记忆**——下次写新项目时，你能直接说"这块照 TRL 的写法、那块照 Open-R1 的写法"。

## 二、阶段三具体学什么

### 三个阅读对象

| 项目 | 定位 | 我们读什么 |
|------|------|-----------|
| **TRL**（HuggingFace） | "训练器层"工具库 | `SFTTrainer`、`GRPOTrainer`、`DataCollatorForCompletionOnlyLM` 等核心类的源码 |
| **Open-R1**（HuggingFace） | 完整可运行项目 | 项目架构、训练入口脚本、配置体系（YAML）、奖励函数设计 |
| **SimpleRL-Zoo** | 小模型 RL 实验框架 | 小规模实验代码、超参数、评估流程 |

为什么是这三个？
- **TRL**：是几乎所有后训练项目的"地基"。读懂 TRL，就读懂了 80% 的训练循环。
- **Open-R1**：DeepSeek R1 的官方开源复现，最贴近你阶段四要做的项目。它告诉你"一个完整 RL 推理项目长什么样"。
- **SimpleRL-Zoo**：小模型 RL 的最佳参考，很多设定可以直接迁移到你阶段四的小卡环境。

## 三、阶段三的硬约束

### 约束 1：普通电脑能跑

阶段三**禁止依赖专业显卡**。所有动手环节必须在普通笔记本（CPU 或 ≤ 8 GB 显存）上几分钟内跑完。

具体策略：
- **结构理解类**（架构图、调用链、文件关系）：只读源码 + 画图，**不运行**。
- **数据/Tokenize/Reward 类**：用切片到 ~100 条的小数据集 + 小模型（`Qwen2.5-0.5B`、`gpt2`、`TinyLlama-1.1B`），CPU 直接跑。
- **Trainer/训练循环类**：设 `max_steps=2`、`per_device_train_batch_size=1`，**只验证代码能走通、shape 对得上**，不看收敛。
- **GRPO 采样类**：把 vLLM 替换成 `model.generate()` 的 toy 版，`num_generations=2`、`max_new_tokens ≤ 64`。
- **完全跑不动的环节**（完整 RL 训练到收敛、大模型推理）：**只读不跑**，明确标记"留给阶段四"。

### 约束 2：不追求训练效果

阶段三**不看 loss 曲线、不看任务指标**。目标只有三个字：**看懂、跑通、能复述**。

如果某节课跑出来的 loss 看着很奇怪——只要能算出数、shape 对、链路通，就是过关。"训练好不好"是阶段四的事。

### 约束 3：理论只做映射，不做推导

遇到阶段二涉及的公式（SFT loss、advantage、KL 罚项），**用一句话说明这段代码对应那个公式的哪一项即可**，不重新推导。

理由：阶段二已经推过，阶段三的注意力要全部放到工程上。

## 四、学习方法与授课节奏

### 授课节奏：工程优先 + 适度动手

阶段三**固定一种节奏**——不再像阶段二那样按"严谨派/直觉派"切换。重点放在工程落地：

- 数据集长什么形式？字段叫什么？要做哪些预处理？
- 用了哪个 trainer？关键参数有哪些？哪些参数显著影响显存/速度？
- 数据怎么 batch、mask、padding？这些步骤在源码哪一行？
- 模型怎么加载、怎么被 LoRA / DeepSpeed 包装？
- 训练循环里哪几步是必经之路（forward / loss / backward / step / log / save）？
- 有哪些常见踩坑点（chat_template、pad token、reward 数值范围……）？

### 每节课的 6 步流程

每节正课固定走这 6 步：

1. **开课导言**：查进度、确认环境、说明本课位置和目标。
2. **今日代码地图**：今天读哪几个文件？它们什么关系？用一张表 + 一张图说清楚。
3. **主文件结构导览**：宣布今天主讲哪一个文件，画出它内部由哪几个 section 组成。
4. **模块精读**：按 section 一段一段讲。**一次只讲一个，等你说"继续"才讲下一个**。每段代码必带"三行头部"——来源 / 作用 / 工程要点。
5. **本机跑一跑（含断点调试）**：写一个 toy 脚本 `lessons/cr_lesson{NN}_runme.py`，2-3 个观察点，让你**亲眼看到中间张量长什么样**。每节课至少演示一次 `breakpoint()` 或 VS Code 断点。
6. **小任务考核 + 总结打卡**：2-3 个小任务，重点是读懂代码、观察中间变量、修改参数并解释现象；不要求从零手写完整训练代码。

### 调试是工程的核心技能

阶段三特别强调一件事：**代码看不懂就打断点，别反复读静态源码**。

工具栈从轻到重：

| 方式 | 适用场景 |
|------|---------|
| 战略性 `print` | 快速看 shape / dtype / 前几个值 |
| `breakpoint()` + pdb | 想交互式探索一个对象的所有字段 |
| VS Code 调试器 | 想可视化变量、设条件断点、跨文件单步 |
| `"justMyCode": false` + F11 | 想步入 trainer 内部，看真实做了什么 |
| Monkey-patch | 不改第三方源码也能抓中间值 |

养成"看不懂 → 打断点 → 看真实数据"的反射，比看十遍源码更有效。

### 考核形式：读代码、看现象、改参数

阶段三**不用选择题、不用填空题**。每节课的小任务可以包含运行脚本和调试观察，但目标不是考纯手写代码，而是训练你读懂开源项目、理解原理、审查 AI 生成代码、修改关键参数的能力：

- 在 runme 里把某个开关（如 `packing`、`use_peft`）切换，记录 batch shape / 可训练参数变化；
- 用 `breakpoint()` 进入 collator，导出 `batch` 字段名 + shape + dtype 表；
- 用 VS Code 断点 F11 步入 `SFTTrainer`，找出真正算 loss 的那一行；
- 故意制造一个常见 bug（忘设 pad_token），观察报错并修复；
- 审查 AI 生成的 trainer 配置，指出哪些参数不适合当前机器；
- ……

通过标准改为：**定位到相关代码 / 参数 + 一句话解释原理 + 给出修改建议或输出截图**。阶段考试尤其不要求从零手写完整训练脚本或完整 reward 函数。

## 五、给你的几个心态建议

1. **不要逐字读完每一行源码**。一个文件可能 2000 行，真正关键的就那 200 行。学会跳读、抓主干。
2. **看不懂很正常**。第一次读 `SFTTrainer` 一定有大量"这是干嘛的？"的疑惑——这正是要打断点、对照阶段二理论的时机。
3. **不要追求"看完"**。阶段三不发证书。看完 10 节课不重要，重要的是你**手上有一份能在阶段四复用的工程清单**。
4. **遇到陌生 API 不要慌**。HuggingFace 系生态接口非常多（`Trainer`, `TrainingArguments`, `DataCollator`, `processing_class`...），先抓住"它是输入还是输出？是数据还是配置？"两个问题，足够推进 90% 的阅读。
5. **保留疑问**。读不懂的细节用 `# TODO 阶段四再看` 标注，不要陷在某一行卡住。
